# Adequacy, precision and research contribution

## Evidence matches the task

| Stage/use | Useful evidence | Meaning of completion |
| --- | --- | --- |
| Exploration | Declared closed model, essential units/conditions, a cheap limit or baseline, relevant QoIs and rough error scale | Informs feasibility or the next question; no claim of real-system validation |
| Argument formation | Reproducible claim-specific comparisons, numerical adequacy, credible referents, uncertainties and alternatives | Supports or revises a bounded argument and the next investigation |
| Consequential manuscript claim | Current bindings, relevant reproducibility checks, appropriate validation alignment, independent review and counterevidence disposition | Supports exactly the stated claim or records why it remains unsupported |

Stages can move backward. A manuscript may report useful model-internal or exploratory findings when that scope is explicit. These labels are work modes rather than quality certificates.

For each consequential QoI state its definition/unit, decision served, effect scale, error evidence, input/model uncertainty, adequacy criterion and rationale. A field peak may need a different numerical check from an average flux; residual tolerance alone does not establish either. Choose appropriate limits, benchmarks, refinement, conservation or error estimators. Do not impose one universal percent error.

Set a pass/validation criterion before the consequential comparison. If the question or use changes, create a new version and explain it; do not tune criteria after seeing the answer to rescue failed evidence. Provisional exploratory judgments remain labeled provisional.

## Two-sided stopping judgment

Another mesh or time-step refinement is useful if it could change a comparison, expose a consequential failure or distinguish explanations. Extra digits alone are not research progress. Conversely, an effect within numerical uncertainty, a reversed ranking, violated balance, wrong conditions or leaked validation data requires correction or narrower scope even when the project needs a finished paper.

After two attempts with no such change, return the observations, affected claims, cost and alternatives. This is a reassessment point, not a mathematical convergence rule. Continuing requires a bounded reason for expected new information. Report actual solver calls and costs when known; a framework-level attempt can contain many internal runs and does not automatically meter them.

## Return the specialist explanation

Use a compact result file with:

- assigned question and bounded answer;
- input/run versions, conditions, solver/environment and actual artifact paths;
- observed QoIs, numerical variation and uncertainty;
- checks completed/failed/nonapplicable, with their scientific significance;
- hypotheses supported, contradicted or still unresolved, without changing raw data;
- contribution to the pending decision and evidence usable by downstream analysis/writing;
- limitations, costs and the cheapest informative next option.

The specialist explains numerical and physical adequacy. The coordinator interprets project contribution and chooses resource allocation; the mechanism analyst evaluates alternatives. Delivery can be accepted when it provides trustworthy negative evidence while the original hypothesis is rejected.

A hard scientific failure stays failed for the affected claim. A narrower claim explicitly retires the original stronger statement, and retaining an ambiguity can be appropriate when no useful next run is justified. Neither a coordinator decision nor a majority vote converts a factual failure into adequate evidence.
