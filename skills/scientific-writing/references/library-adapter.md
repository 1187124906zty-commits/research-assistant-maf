# Optional structural-library adapter

Read when the supplied external library uses this schema. The generic selection contract is in [library-use.md](library-use.md#selection-contract).

When an external library is supplied, inspect its `general/usage-index.json` sidecar and use the available structural query: `python scripts/query.py --mode structural --section Introduction --position section_end --purpose research_objective --contract PATH`. Run this command from the supplied library root and prepare the contract using that library's documented schema. `object` contains `name`, `type` and `introduction_status` (`new` or `introduced`); `slots` supplies the candidate's required arguments, and optional `choice_ids` selects language/collocation IDs with reviewed bindings. Typed slots use `{value,entity_type}` as documented by the candidate. An unfilled required slot must never be treated as ready. Choose the section, position and purpose actually assigned, rather than reusing this example for every passage.

Inspect `candidates[].contract_assessment.status`: `ready_for_adaptation` means supplied fields and reviewed bindings fit, `needs_slots` means required information is absent, and `blocked` means the object/status/type or chosen language binding is incompatible. None verifies scientific truth. An exact combination with no reviewed record remains unclassified; do not broaden the section or position silently. For example, `Methods × subsection_opening × model_adoption` and `Methods × paragraph_middle × model_referent` perform different jobs; the latter requires an introduced object.

The schema-1 sidecar's reviewed `target={section,position,purpose}` records editorial recommendations. Its positions are `section_opening`, `subsection_opening`, `paragraph_opening`, `paragraph_middle`, `paragraph_end` and `section_end`. Purposes include `object_background`, `literature_synthesis`, `problem_tension`, `research_objective`, `design_rationale`, `bounded_contribution`, `model_adoption`, `model_referent`, `operational_definition`, `protocol`, `comparison`, `candidate_explanation`, `boundary`, `next_test` and `bridge`. Preserve `source_location` and `source_position` separately; an unverified source position is not the paper's observed position. One passage can need more than one move, and different passages need different moves.

Inspect the returned candidate's source locator and read the original passage with neighboring sentences when adopting its argumentative use. Confirm what its object denotes, which proposition precedes it, what evidence earns its assertion, and where it appears in the source. Keep the library's intended target, actual source section/position and present adaptation distinct. A sidecar or query candidate is a lead, not a ready-made sentence or evidence for this study. If the original is unavailable, retain the retrieval status and avoid attributing an unverified source convention. Use the supplied terminology only when the same scientific relation holds.

Where a record has `entry_kind=source_move`, inspect its separately audited raw-context locator, observed source position, neighboring-context summary and transfer boundary. Its `adapted_template` remains an editorial synthesis; it is not a quotation or universal rule. An observed source position may use a descriptive label such as `first_sentence` or `last_paragraph_opening`; keep it independent of the target vocabulary. A few verified source moves do not promote older unverified locations or establish full-library coverage.
