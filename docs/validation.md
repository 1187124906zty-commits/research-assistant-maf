# 验证范围与使用评价

这份记录区分软件路径、模型实际协作和科研效果。运行成功不等于科学判断正确，也不证明发现速度提高。

## 本地软件验证

2026-10-01，在 Windows、Python 3.12.14 上使用 `agent-framework-core==1.19.0` 完成 66 项测试。可重复命令：

```bash
python -m unittest discover -s tests -v
python -m research_assistant demo ./local-runs/demo
python -m pip install build
python -m build
python scripts/check_installed_wheel.py
```

测试包含实际 MAF 图的派发、汇合、独立评阅与处置，而不只是 schema 验证。覆盖行为包括：

- 负面结果作为有用交付接收，原假设保持未支持或暂存。
- 数值核验不能直接晋升为物理验证；反证只影响相关论断及依赖。
- 未改变研究认识的重复返回要求策略重审，循环结束不自动接收科学结论。
- 局部上下文保留声明输入与相关论断；不传入完整事件历史。
- 未声明证据、输入变动、返回后产物变动、同批汇合前变动被拒绝。
- 第二个契约无效时，整个批次与研究计划保持未提交。
- 中断后重新进入当前科学状态，不重复已完成的专业任务；未知外部调用不自动重放。
- 循环预算显式扩展及缺失输入处理后重开，使用新的规划代次。
- 已知无效处置获得一次纠正机会；再次无效或提供者失败均停止，不隐藏重试。
- 并发运行者在创建和保存执行会话前被排除。
- Windows 旧字符编码无法显示科学符号时，JSON 输出转为合法转义，已完成任务仍返回正确退出码。

提供者测试以受控 SDK 替身验证结构化输出、线程归属、超时、取消和严格 JSON 解析，不能单独证明线上模型行为。

源码包和 wheel 已构建成功。安装包检查在源码目录之外安装 wheel，核对实际导入位置、包内技能及引用文件，然后执行真实 MAF 离线演示，避免依赖源码目录使安装检查产生误判。

## 独立检查

独立 agent 根据实际实现建立了上下文、缓存、陈旧证据、恢复、纠正反馈和提供者错误的测试。评审发现的问题由协调者修正后验证。此处的独立指职责与初始检查材料分离，不意味着模型误差统计独立，也不能替代真实同行对科学内容的评阅。

## 真实 Codex 协作验收

真实账户接入和多角色验收使用可选 `openai-codex==0.159.3`。验收范围仅为给定合成数值的描述、文件交接、原件评阅和简短报告；没有启动物理求解器或开展真实实验。最终状态与公开样例见 [协作样例](../examples/live-coordination/README.md)。

实际运行完成两个专业循环，最终状态 `complete`，协议审计没有未闭合交接或陈旧证据风险；审计的科学有效性字段仍为 `not_judged`。专业分析与写作各一次、评阅各一次；已完成专业任务在两次开发期恢复中均未重复执行。

这个验收用于发现只靠确定性返回不容易暴露的交接与规则理解问题。不能用它推断复杂文献调研、数值模拟、机制发现、投稿质量或效率收益。

## 后续科研效果评价

应在明确领域任务上评价实际行为：投入是否改变研究判断，是否出现无意义的追加计算，负面结果是否改变后续安排，机制解释能否追溯到证据，稿件是否保留限制，以及达到指定交付所需的人类干预和计算成本。先记录这些事实，再比较人工协作或既有流程。

当前未进行这样的效果实验。外部求解器作业的提交、查询、取消及资源计数需要专用适配器；操作系统隔离、所有模型提供者、所有专业软件与自动投稿服务也不属于已验证范围。
