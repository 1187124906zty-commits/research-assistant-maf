## 1. 先把问题定义正确

用户要求的是一篇有充分研究背景、专业表达、可靠论据和完整论证的研究论文。深度来自对研究线、最接近工作、证据关系和竞争解释的分析，不能用篇幅、引文数量、角色数量或调用次数代替。

进一步的表达要求见 [摘要与引言定位](abstract-introduction-positioning.zh.md)：将领域困境、具体知识缺口和技术检验分开；主问题采用陈述式论证；摘要凝练且突出特色、回应困难；参考数量与分析颗粒度实际对齐可比样本。内部细问题不直接作为论文开头的科学定位。

对已有稿件的来源错配、解释边界、章节衔接和实现细节过载，使用 [论文审查模式](manuscript-audit.zh.md) 派发有限修复任务；该模式复用现有角色，按实际原件、修复稿与页面闭环，不以协议通过代替内容判断。

本次诊断的依据是当前论文、文献档案和实际 MAF 运行，而不是对系统能力的设想：

- 原有学习集确实阅读过六篇不同的相关原始工作；不能说完全没有参考文献。但目标期刊全文样本主要是 2018、2020、2023 年的论文，2024 年候选仅部分核实，尚未完成 2025–2026 年研究追踪。
- `examples/ammt-manuscript/run_workflow.py` 仅安排机制与结果讨论两项任务，明确禁止文献检索和新 PDE 计算。writer 没有依赖 mechanism 的输出，全文组装由外部主代理承担。这不是完整的章节研究团队。
- `CodexProvider` 每次请求启动新线程。现有任务结果和处置会进入后续上下文，但没有稳定的章节负责人、章节研究记忆或会话续接接口。
- 引用、数值和排版复核修复了一些真实缺陷，不能据此认定近期文献覆盖、贡献竞争力和全文论证已经充分。
- 当前 MAF 完成条件检查交付文件与协议审计；没有原生检查引言承诺是否被结果回答、讨论是否完成解释，以及所审版本是否就是最终全文。

因此需要补的是**论文研究与编辑闭环**，不是再添加一个笼统的 writer。

## 2. 责任划分：研究目标与论文论证分别有人负责

| 责任 | 决策范围 | 实际交付 | 不应承担的越权职责 |
|---|---|---|---|
| 项目协调者 | 研究目标、范围、优先级、资源与阶段；最终对用户负责 | 当前决策、派发合同、结果处置、范围变更 | 凭通用判断推翻有原始依据的专业反证 |
| 科学编辑 | 领域困境、文献缺口、工作响应、独特价值、贡献边界、读者顺序与全文整合 | 分层论证地图、章节承诺、重点摘要/引言修订、整合稿 | 由技术任务倒推宏大 gap，或以表达力度填补不存在的证据 |
| 章节负责人 | 所负责章节的定向调研、论证、写作与修订 | 来源笔记、段落论证、章节稿、跨章节问题 | 擅自扩大贡献、直接覆盖他人章节或全文 |
| 文献协调职责 | 检索去重、文献身份、全文获取队列、近期研究与反向/正向追踪 | 共享来源索引、阅读状态、尚缺证据 | 只用摘要替别人完成详细方法或机制判断 |
| 专业证据角色 | 模型、实验、统计和机制的具体疑问 | 有条件与可定位依据的专业回答 | 为了叙事需要追求无关的理想精度 |
| 独立全文评阅者 | 实际整合稿是否成立、可读、充分，及其与原文和期刊样本的关系 | 定位到段落/图表的实质问题与修复条件 | 将文件检查、长参考文献表或章节自评当作同行评审 |

这些是逻辑责任，不是必须同时运行的六种常驻 agent。项目协调者可兼任科学编辑，但两种判断要区分：一个结果对项目有用，不代表其所在章节已写好。初期使用协调者加两至三个活动专家，章节负责人按阶段轮转。

研究状态只设一个权威写入者。ResearchFlow 与 MAF 跨库交接用版本化输入和明确处置，不让两个协调端同时改同一科学结论。论文编辑状态另外记录章节、来源使用和修复问题，并引用科学证据；不复制出第二套真假相互冲突的科学事实。

## 3. 每节接受的是一项论证责任

### 科学矛盾如何进入整篇论证

领域已经有大量研究，不妨碍继续开展有价值的有限工作。编辑必须先从真实近邻原文确定共同关注的矛盾、已经解决的部分及当前条件下仍需分解的认识，再选取现有结果能够回答的研究点。不能从已经运行的变量倒推一个宏大空白，也不能照搬旧论文的“尚未解决”作为今天的事实。新文献改变定位时，标题、摘要、引言承诺和讨论需要一起调整。

摘要与引言建立文献支持的科学矛盾和工作必要性；方法将其转换为具体因素、控制条件、观察与判别逻辑；结果给出全面且有条件的定量比较；讨论解释与既有研究的关系及竞争解释；结论将获得的认识接回起初的矛盾。每一层允许不同的表达尺度，但不能有相互冲突的承诺。少量定量验证支持有限贡献，也可以形成完整初稿；“完整”不表示模型已经物理验证或期刊必然接受。

所有章节先读同一份简短的论证地图：研究问题、读者为什么在意、已有研究已解决什么、本研究能回答什么、不能声称什么、结果次序、术语定义。各自只深入读取相关原件和相邻接口。

| 章节 | 应回答的问题 | 必需的定向研究 | 交付与接受依据 |
|---|---|---|---|
| 引言 | 建立领域困境、研究必要性与文献支持的缺口，再收束到本工作 | 历史研究线、近期最接近工作、已解决的部分、真实剩余问题；相邻领域的可迁移解释 | 充分铺垫后以陈述式 gap 建立必要性，末段特色回应困难；细变量不占据开头，旧论文的 gap 不直接当作今天的 gap |
| 方法 | 为什么这个设计能回答上述问题？读者如何复现与质疑？ | 方程和方法原始来源、近邻比较的条件、测量定义、校准和比较角色、合理的数值证据 | 自洽的方程/单位/边界/参数/算法/观察算子；设计理由与引言问题对应；细节按复现必要性放正文或补充材料 |
| 结果 | 证据按什么顺序改变认识？ | 读懂本研究原始结果；必要时核对同类研究的观察定义，避免提前引入未检验解释 | 每组结果有一个问题、关键对照、支持的结论和下一问题；重要数值与图表绑定来源；不按运行日志顺序罗列 |
| 讨论 | 发现相对先前研究改变了什么认识？还有哪些解释？ | 最接近工作的结果和讨论原文、支持与相反证据、机制条件、未控制差异 | 有条件地比较一致与差异；明确哪些是本文推断；解释与证据层次匹配；局限改变具体解释而不成为反复的免责声明 |
| 图表及图注 | 读者能否直接看懂关键比较及其证据范围？ | 目标期刊中承担相似科学任务的真实图表；当前指南 | 图、图注、正文一致；观察定义、样本/条件、单位、误差含义完整；面板各有作用，实际版面可读 |
| 标题、摘要、结论 | 凝练领域意义、关键困境、工作特色和被证据支持的认识推进 | 已接受的整合稿、可比摘要/引言原文与当前期刊要求 | 摘要选择关键发现回应困难，不逐节复述；主要承诺由正文兑现，必要范围集中表达 |

一节可有多个小节负责人，但不能把主论证切成彼此不知目的的碎片。Results 与 Discussion 是否合并由题目和真实期刊惯例决定，不能机械强制 IMRAD。

## 4. 文献工作贯穿各节，而不是写作前完成一次搜索

文献协调者维护共享目录，章节负责人提出具体阅读需求并负责解释。来源可承担背景、方法依据、最近对手、机制解释、反证、期刊表达样本等不同作用。同一篇论文可被多个章节使用，但不算多次独立检索成果。

本案例的下一轮覆盖范围是基础研究加 **2024 年至 2026-10-01** 的近期工作；这是本次检索的截止日期，不是已经覆盖完成的声明。按研究问题分别检索物性高温延拓、热源/有效参数标定、熔池几何与热场约束、观察算子与不确定性，以及传导与流动模型的解释边界。对最接近工作做参考文献回溯和后续引用追踪。补充与中心论断冲突的研究，不能只收集支持材料。

先核实题名、作者、年份、期刊、DOI和版本。需要判断创新差异、算法细节、图表、机制或定量比较时阅读对应全文和原始图表。背景性概述可按实际可得摘要支持的范围使用。每次阅读写清“原作者发现—适用条件—对本研究的关系—不能推导什么”，不要把模型记忆当文献事实。

来源记录只保留有用字段：

```text
source_id / DOI / version / access_url
read_scope: metadata | abstract | relevant_sections | full_article
local_path / page_or_section / actual_passage_or_figure
function_in_paper / supported_statement / conditions
our_inference / contradiction_or_limit / intended_section
```

关键引用要查到使用位置；来源索引不是强迫每篇全文逐字阅读的门槛。参考覆盖与分析深度依据具体论证、研究线、方法出处、机制和反证判断，并对照实际相近论文。R2 曾依据三个样本 43/17/52 条制定暂定 38 条目标，后续协调者已取消将样本均值作为最低数量；旧稿 13 条是历史起点。当前不以条数认证文稿，也不以“避免堆砌”为由跳过缺失的关键来源。期刊偏好服从真实内容匹配，未取得的全文和未完成的来源用途继续如实标记。

出版商全文缺失时，使用已授权的 `sciencedirect-live-session-fetcher` 会话流程；出版社下载由统一队列串行执行，避免各章节同时争抢同一浏览器。身份认证或验证码只有在确实出现时交由用户处理，继续其他不依赖该全文的任务。此前没有成功取得的机构 PDF 继续标为缺失，不能因读过摘要改为已读全文。

当前没有批内下载 broker，首轮在阶段边界交接：worker 将缺失来源、DOI/已知 article URL、所需章节和用途写入自己的声明来源请求文件，先返回已完成的有限判断，不在批内等待协调者。批次结束后协调者统一获取、登记真实文件，再建立有新输入的续研究合同；可以提前集中取得已知关键全文。部分检索交付的接收不表示原文学习已完成，未回答的原研究问题继续保留。

## 5. 期刊学习要产出写作决策

分开记录：**当前官方硬性要求、相关已发表论文的观察惯例、为本研究作出的编辑选择**。样本惯例不能假装成投稿规则，也不能只按刊名泛泛模仿语气。

选择题目、文章类型和证据形态可比的文章，并补入近期样本。相关论文可以同时教科学背景和表达，但来源的两种用途要说明。读引言段落的推进、方法的理由与颗粒度、结果和图表的出现顺序、讨论如何引用不同意见、摘要和结论的边界。视觉学习应查看真实 PDF 的图、表、图注、正文和参考文献页面。

下一轮深入学习采用六篇同方向研究与六篇不同的目标期刊研究型样本，不重复计数；尚未完成的篇目继续如实标注。记录 reference 分布、各节分析颗粒度、摘要与引言的困境—特色关系；引言充分研究后凝练，不以空泛长背景代替必要铺垫。摘要和引言获得专门表达迭代预算，不机械地和其他章节等额分配。

学习结果必须对应下一项改动，例如：“先定义长度测量与熔合边界，再比较三维几何”“Discussion先回答引言承诺，再解释高温闭包差异”。数字、行文和版面均在实际稿中复查；复制已发表论文的措辞、刊物品牌或 DOI 不属于期刊适配。

当前 AM 指南有访问障碍，部分要求未核实。下一轮可以继续文献与论证，具体摘要限字、匿名评审、必需提交文件和图像规则要在合法可读指南中确认，最终交付如实披露缺口。

## 6. 定向交互，不建立全员互聊

科学编辑建立以下必要接口，每次交换固定版本并提出一个问题：

- **引言 ↔ 方法**：末段承诺能否由设计回答？哪些必须先定义的观察/假设仍缺失？
- **方法 ↔ 结果**：比较对象、计算/测量算子和误差含义是否一致？每项结果能否追溯到设计？
- **结果 ↔ 讨论**：解释是否超出结果？哪些负面结果或替代解释被遗漏？
- **引言 ↔ 讨论**：讨论是否回答开头的问题？近期文献是否使原来的 gap 失效？
- **图表 ↔ 相应正文**：读者看到的图是否支持正文和图注相同的主张？

章节负责人在任务中返回接口疑问，由编辑筛选后形成显式 review 任务。评阅者输出问题，不直接改对方章节。修复由原负责人完成；请求方解释修复是否解决了接口问题。重要反证交给协调者更新受影响论断，不能以多数 agent 同意作真理判据。

证据独立检查与稿件忠实性检查分开说明。先看原件可以降低锚定，但要评判写作就必须再实际读被评稿件；不能只核对数据、未读章稿却宣布章稿通过。各类评阅记录实际检查的文件版本与位置。同模型多代理提供角色隔离，不建立统计独立性。

## 7. 长期记忆与版本

先保障责任和记忆持续，再考虑模型线程持续。单次 SDK turn 可以包含多次工具调用和内部修订；“每次任务新线程”不等于“只能思考一次”。但是，章节跨阶段的取舍不能只藏在临时对话中。

每次任务输入：共享论证地图、自己已接受的研究记忆、必要来源/数据定位、受影响相邻章节、当前具体问题、输出与返回条件。章节记忆保存比较结论、段落意图、被否定路径及原因、未解决问题和下一步；不会把全部历史聊天复制给每人。

建议的版本布局：

```text
paper-work/
  manifest/argument-r001.json
  literature/sources-r001.json
  journal/profile-r001.md
  sections/introduction/r001/{memory.md,argument.md,draft.md}
  sections/methods/r001/{memory.md,argument.md,draft.md}
  sections/results/r001/{memory.md,argument.md,draft.md}
  sections/discussion/r001/{memory.md,argument.md,draft.md}
  exchanges/<issue-id>/review-r001.md
  editorial/issues.json
  editorial/heads.json
  integrated/r001/{manuscript-source.txt,review.md}
```

这是未来任务产物的布局，当前未创建占位研究结论。版本化章节文件不覆盖旧版，编辑单独更新 accepted head。最终 LaTeX 仍编辑用户正在打开的 `paper/ammt-study/manuscript.tex`，不换文档；只有整合者写该文件。内部版本用于比较与评阅，不生成另一篇替代论文。

一次新文献或数值反证只使相关段落和依赖失效。编辑提出的中心贡献变动影响标题、摘要、引言承诺、结果与结论；这种变动需要整条论证重新核对。普通标点修改不要求重审全文。可选同章节会话续接是后续优化，不能代替上述记忆、原件与失效处理；独立评阅使用新的上下文。

## 8. 深入与效率如何同时成立

各负责人在一个有明确问题的任务内可持续检索、反复思考与修改。预算用来决定何时回报和重新评估，不是要求尽早交稿。阶段产物应先回答研究问题，再写段落，最后调整句式。

分开报告两类进展：

- `scientific_delta`：新证据、改变贡献差异、排除解释、修正方法判断、收窄论断。
- `editorial_delta`：补上推理桥梁、兑现章节承诺、去除无支持表达、改善术语/引用/图文关系。

当前 `changed_understanding` 不能靠将纯文字修改填为 true 来绕开预算。原内核尚未阶段化，使用诚实结果与有理由的 reassessment；应用层后续增加进展类型和对应阈值。科学认识未变化仍可以有必要的编辑进展。

临时执行映射：没有科学认识变化就返回 `changed_understanding=false`，把已解决位置、前后差异及尚未解决问题写进声明产物中的 `editorial_delta`。触发现有阈值时，协调者读取该产物，明确追加为什么能改善稿件，再提交有理由、有有限额的 reassessment。编辑记录按同一 `issue_id` 累计尝试与费用；因输入变化建立的新合同关联原问题，不用新 task id 擦除先前预算。以上计账由协调者执行，尚不是内核自动检查。

连续两次对同一问题没有科学或编辑改善，先回到协调者重新判断：缺的是文献、证据、结构、任务定义还是当前方法？有新证据或具体未修复缺陷就继续；仅做同义词替换、重复搜索或追求与结论无关的更高精度就换策略或结束该项工作。不得通过不断新建阶段任务重置预算。

调度优先解决能改变贡献定位、解释范围和读者理解的问题。文献获取去重，方法与原始结果审查可并行；讨论的最终解释依赖已处置的结果和近邻比较；摘要最后写。先使用现有 batch barrier，在阶段边界交换，只有实际观察到等候浪费才改成事件驱动流水调度。

## 9. 最小应用层扩展与实际边界

| 能力 | 当前状态 | 最小处理 |
|---|---|---|
| 有界任务、输入绑定、结果与请求者处置、独立 reviewer | 已实现，并有真实有限案例 | 保留，不宣称因此获得科研质量保证 |
| 持久章节责任与论证地图 | 未原生实现 | 首轮用显式声明的输入/输出文件；随后增加 manuscript manifest 和 section/owner/phase 绑定 |
| 定向跨章节评阅 | 未原生实现 | 先作为有固定双方版本的独立任务；增加 ReviewSpec 与 editorial issue 记录 |
| 章节推理记忆、不可变修订产物 | 有文件读写与版本绑定基础，无章节语义 | 保留每版文件和接受指针；派发恢复需要的部分 |
| 科学与编辑进展分离 | 未实现 | 增加 progress 类型；科学证据提升规则保持原含义 |
| 同章节线程续接 | 未实现 | 先用文件记忆正确运行；按实际 SDK 能力验证可选 continuation |
| 全文完成条件 | 现有条件仅覆盖文件/协议 | 核对当前接受章节、接口问题、实际整合稿与独立评阅的同版本绑定 |

现有严格 schema 不接受随意添加字段。第一轮章节元数据放在已声明 artifact 中，用现有 literature/mechanism/writer 角色即可；未来正式加字段须版本化 schema、兼容旧状态并验证。`depends_on` 中任务 closed 不等于产物已接受可用，论文层要判断 accepted head。更新输入或研究问题要新建明确合同，不能假设 continue 自动更新原 frozen inputs。

实际派发入口增加 accepted-head 检查：协调者读取 `editorial/heads.json`，每个采用的条目明确 section/phase、实际 path/revision、接受理由和有关接口处置；确认文件仍对应该版本后，冻结为合同 inputs。恢复时重新检查接受指针；若指针已变则重新核对依赖并建立更新合同，不能继续使用旧输入。parked/reframed 的产物可作为带标签的历史背景，不能充当当前已接受章节。首轮该步骤由协调者明确执行；自动校验属于应用层扩展。

`evidence.path` 使用真实文件路径；DOI、URL、页码、行号和 JSON selector 分开保存。角色不能把新下载文献的任意路径直接塞入返回：最小可行做法是预声明自己的来源产物目录，返回的资料保存在允许写入范围内；既有外部原件以固定输入绑定。下一阶段正式声明返回中采用的版本。审查源网页或本地全文不等于已获得外部发布许可。

无需重构上游 MAF。需要修改的是本项目任务包装、状态和 reviewer 请求。变更后既要跑受影响测试与实际 MAF 工作流，也要用本案例验证定向交换、修复恢复与全文整合；演示预设返回不能替代真实模型验收。

## 10. 分层交付判断

论证设计可进入写作：中心问题有据、近邻差异已查、现有证据能回答所承诺问题。重要问题尚缺证据时，写作使用有边界的结论或明确返回研究任务。

章节可进入整合：承担的问题已回答，关键引用与原件关系可靠，必要接口已处置。副要的表达改进不必成为阻断其他章节的原因。

整合稿可交付评阅：引言、结果、讨论和结论一致，关键图表完整，独立读者实际阅读整合稿并指出具体剩余缺陷。独立 agent 评阅是预审支持，不是期刊同行评审。

可向用户交付的初稿、期刊格式核实、科学成立、适合目标期刊、可正式投稿是不同判断。未解决核心证据问题不能被排版 PASS 清除，期刊指南缺失也不能虚报合规。旧稿发布在实质修订期间暂停；当前 R2 已完成整稿评阅、三项问题修复和受影响输出复核，以证据范围明确的初稿状态交付，保留科学与投稿限制。

## 11. 本案例采用的执行顺序

初始设计阶段先完成整体诊断、职责与版本方案，不立即改稿；用户随后授权在已有结果基础上执行完整修订。实际按 [AMMT 实质修订任务](../examples/ammt-deep-revision/README.md) 推进：先近期研究线与期刊学习，同时审查方法—观察关系；编辑据此修订贡献定位；再安排章稿、定向互审、全文整合和独立实质评阅；最后编译、检查实际 PDF 与源码包并整理 GitHub 展示。原生 MAF writer 批次部分成功且超时，后续整合与评阅由 Codex 专家真实完成；该运行限制保持可见。

方法来源：ResearchFlow governor 的用途驱动派发与请求者处置；PaperSpine 的 journal-learning、motivation-thread-writing、editorial-completeness、assertive-scientific-writing 与 production protocol。这是对本项目应用层的设计，未修改或声称升级了 PaperSpine 产品。
