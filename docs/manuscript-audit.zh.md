# 论文审查模式：从原件到可读论证

本模式用于已有论文的定向诊断与修订。它针对实现细节挤占论证、引用只按题名匹配、具体因素讨论借用宽泛背景来源、标题和句式生硬、章节衔接不足等问题；不把增加篇幅、引用或角色视为改善。它是现有角色的工作指令与任务方法，不是新的运行时角色，也不是内容质量自动判定器。

## 责任与路由

协调者指定一名科学编辑，由现有 `coordinator` 或单独的 `writer` 任务承担，并与具体章稿写作分清责任。编辑对整篇稿件的读者顺序和论证负责；专业来源与解释判断仍交给对应角色。

| 现有角色 | 本轮负责的问题 | 有限返回 |
|---|---|---|
| coordinator / writer（科学编辑职责） | 本节为什么存在、如何承接已有认识；段落顺序、节奏、标题与信息分配 | 定位到段落的编辑判断与修订指令，不以表达填补证据 |
| literature | 这句话是否被原文的实际内容和条件支持；方程与参数从哪里来 | 原件定位、支持范围、必要收窄或替代来源 |
| mechanism | 观察支持哪一层解释；哪些竞争解释还成立 | 证据—解释边界、替代解释及有意义的判别需求 |
| writer | 按已核对来源和编辑意图修改具体段落 | 实际章稿、已修位置与未解决问题 |
| reviewer | 修改后的源码和页面是否真正解决问题 | 独立的定位问题与修复核验，不凭写作者自评通过 |
| coordinator（闭环职责） | 修复是否满足这项任务、影响哪些论断与依赖 | 有理由的接收、部分接收、补证、重定向或保留问题 |

不要求每次同时启动所有角色。一个来源错配可先由 literature 核对再交 writer；涉及因果或跨条件解释时才加入 mechanism。独立评阅使用具体结果版本和必要原件；角色隔离不等于模型误差统计独立。

## 审查的判断依据

期刊要求分三类记录：当前官方指南规定的要求、可比已发表论文中观察到的惯例、为本研究选择的编辑方案。只有第一类可作为强制合规依据；缺失指南要保留缺口。可学习章节组织、图表职责、篇幅分配和表达颗粒度，不逐字复制样本正文，也不把样本的标题或段落安排套到不同论证上。

引用核对以**句子实际声称什么**为起点。题名相近只能帮助寻找来源，不能证明来源解释了特定因素。查看原文对应段落、方程、图表及条件，区分全文事实、摘要可支持的概述和本稿推断。引言中的宽泛综述若不能支持讨论中的具体机制，应补读直接来源、收窄表述或保留为待核。一个来源可用于多处，只要每处用途确实受其内容支持；重复使用不增加独立证据数量，新增无功能引用也不补足覆盖。

方程注明是已发表形式、基于来源的改写，还是本研究推导。改写交代变化和假设；本地推导保留定义、步骤或可检验的推导材料，不能为它寻找貌似对应的引用。参数根据实际角色核对，而非只检查有无引用：物性参数需要测量/来源、单位与适用条件；数值设置需要选择理由与必要收敛证据；拟合参数需要标定数据、目标、约束及其与验证数据的关系。同一量可以承担不同角色，但必须说明本研究如何使用。

机制段落分清观察、模型内解释、文献支持的机制和未检验假说。相似现象不自动建立因果关系；比较条件、未控制差异和存活的替代解释会改变结论范围。不能把补入一篇机制论文当作本研究已经验证了该机制。

## 叙事与可复现信息放在哪里

正文先交代科学问题、模型/设计选择及其理由、读懂结果所需的定义和影响解释的关键条件。软件或实现信息若影响算法行为、误差或适用范围，就说明其科学作用；单纯列出库、agent、命令和数据路径会打断论证。

附录承接需要展开但会压断正文的推导、算法细节和补充检验。复现说明保存依赖版本、命令、配置、输入输出映射及必要路径；来源记录保存原件、数据版本、提取位置和生成关系。按任务需要提供实际可访问的关联位置，保留复现所需材料；移出正文不等于删除或隐藏影响结论的信息。保密或无法公开的资料如实注明可获取范围，不能承诺不存在的复现包。

章节开头需要让读者理解这一节承担什么作用、为何在此出现。可通过承接上一节发现、提出尚待解释的问题、先定义比较对象等语义动作完成；上下文已经清楚时无需重复说明。不要把“上一节……本节……下一节……”变成所有章节统一的路标句。标题应反映该节的实际科学任务或发现，句式选择服务于明确关系，避免机械堆叠名词和过度流程化表达。

## 有限任务与返回

每项任务只契约化一个能改变判断的问题，例如“核对这三句关于某因素的解释是否由给定来源支持，并提出有限修复”。输入包包含固定稿件版本及位置、相邻段落、相关论断、原件定位与已知反证；明确唯一写入路径、接受理由、预算和返回条件。不要派发“全面提升论文质量”后让专家无限搜索。缺少原文时返回已完成部分和具体缺口，协调者决定获取或改变表述。

审查产物采用短记录，详细证据留在关联原件中：

```text
location/version: 稿件段落、方程或图表及实际被审版本
defect: 具体错误、缺口或读者障碍；标明事实/正式要求/编辑建议
source: 原件与页、节、式、表或图定位；读取范围和访问缺口
support: full | partial | absent | unverified，并说明条件
repair: 可执行的修复、收窄或最小判别需求
impact: 哪个科学判断或哪一处读者理解会改变
disposition: 评阅者建议；协调者记录实际处置与核验依据
```

源码位置说明句子和引用关系，渲染页说明读者实际看到的标题、段落、图表及衔接。评阅者要读取修复后的材料才能清除对应问题；页面或原件不可得时明确限制。协调者依据修复后的原件关系和段落作用关闭问题，保留尚未解决的反证及依赖。接收一项写作交付不等于支持其全部科学主张。

## 改善、重审与运行边界

分别报告 `scientific_delta`（新增证据、排除解释、修正或收窄科学判断）和 `editorial_delta`（补上推理关系、改善顺序、删去无支持表达、修复引用与图文关系）。编辑改善可以充分有价值，但不因此提升科学证据等级。连续两次未产生实质科学或编辑改善，协调者先判断缺的是原件、证据、结构还是任务定义；有具体新输入时给出有限续任务，否则换策略或结束该项修饰，不用重建任务清除尝试历史。

这两类进展是产物中的解释，**不是新增 schema 字段**。现有 `changed_understanding` 保持科学认识的含义：纯编辑修改返回 false，在已声明产物中记录已解决位置和前后差异；触发既有重审条件时由协调者提交有理由的有限 reassessment，不能把措辞改动填成科学进展。

`Session.request()` 调用 `role_text()`，将现有角色文件写入模型 instructions；加载时优先使用包内 `resources/roles`，无包内文件才使用仓库 `roles`。本次动作已嵌入角色提示。本说明文档本身不会自动加载，需要作为明确输入派发；wheel 使用者需要更新构建/安装后的包资源。已有保存请求不会自动换成新指令，受影响任务应检查旧返回，再建立明确的新请求与输入绑定，不能假设恢复会刷新审查模式。

协议引擎检查任务形状、文件和依赖绑定，不能判断句子是否被论文内容支持，也不能判定期刊水平。模式是否有效，要由实际任务对修复稿和页面的检查来证明；不能用文档与测试通过冒充真实稿件已完成审查。
