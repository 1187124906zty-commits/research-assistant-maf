# 通用核心与特定案例的边界

Research Assistant MAF 由一个可复用的协调内核和若干任务案例组成。内核负责怎样组织科研协作；案例负责某一研究对象、数据、模型、期刊和交付物是什么。两者必须分开维护，避免一次论文任务把材料参数、工况、结论或领域术语固化成所有任务的规则。

## 通用核心

以下内容属于所有研究任务都可以复用的协议或方法：

- 任务契约：问题、目的、论断范围、输入、输出路径、验收理由、预算和返回条件。
- 协调与状态：并行派发、依赖、检查点、未知调用核实、恢复、负结果和受影响论断的阻塞。
- 角色责任：协调者、文献/证据、机制、写作、评阅以及由宿主提供的领域执行者。
- 写作原则：读者和论证先于章节模板，来源定位先于具体断言，方法与结果按证据依赖衔接，结果和讨论可按解释责任合并或分开。
- 补证流程：写作者发现关键数据缺口后提出有界补证，领域团队执行和审查，协调者接收支持、待证和否证结果，再联动手稿。
- 文件交付：结构化源优先，编辑性、内容完整性、视觉外观和分页分别核验；可编辑转换不能承诺绝对无损。

通用核心不得假定材料、求解器、实验设备、目标期刊、精度阈值、图表数量或某一种论文结构。具体数值容差只能由论断、效应尺度、测量不确定度、数值误差和任务用途共同确定。角色提示也不得把案例中的观察结果写成预期答案。

核心入口包括 `src/research_assistant/`、`roles/`、`skills/`、`docs/` 中的协议文档，以及不依赖研究对象的离线演示和测试。核心角色不会自动读取 `examples/` 中的案例文件。

## 案例层

案例层可以包含：

- 研究问题、材料或样品、实验/模拟输入和原始数据；
- 方程、边界条件、参数、工况标签、观测量和项目特有的精度要求；
- 目标期刊及其作者指南、实际参考论文、图表、手稿、补证运行和人工评阅资料；
- 针对该案例的证据处置、未解决问题、否证结果和交付限制。

案例应放在独立项目目录或 `examples/<case-name>/` 下，并在 README 中说明其输入来源、数据角色、执行范围、验证范围和未完成事项。案例可以调用通用角色和 skill，但不得通过修改通用 skill 来注入案例结论。若需要领域规则，应作为案例任务契约、独立参考资料或显式的领域 skill 提供，并标明适用范围。

本仓库当前的 AMMT/IN625 材料案例、分章写作记录和研究稿仅用于展示真实协作路径。它们不构成 MAF 的默认研究问题，也不构成材料物性、熔池模型、温度区间、实验条件或论文结论的通用模板。完整手稿、PDF、参考原件和人工评估资料保留在对应的 ResearchFlow 研究仓库。

## 新案例的接入检查

提交一个新案例前，维护者应检查：

1. 通用角色和 skill 中没有案例对象、参数、数值结论或隐含的目标答案。
2. 案例的原始输入、文献、数据和许可证范围位于案例目录，并能从 README 追溯。
3. 案例任务明确区分计划、执行成功、数值验证、实验验证、机制解释和期刊交付。
4. 失败、待证和不适用的判断保留在案例记录中，不被通用示例改写为成功路径。
5. 通用测试覆盖协议行为；案例测试另外验证数据和科学对象，不能用案例通过替代通用能力验证。
6. README 将通用安装/使用说明与案例阅读入口分开，读者可以只安装和运行内核而不下载案例资料。
